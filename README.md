# 头马奖状制作工具

这是一个给 Toastmasters 俱乐部使用的奖状制作网页工具。

如果你每次会议结束后，都要给“最佳小蜜蜂”“最佳主持人”“最佳即兴”“最佳点评人”等获奖者制作奖状，这个工具可以帮你把重复工作一次做完。

## 立即使用

1. [下载完整工具包（ZIP）](https://github.com/Regan-Sun/toastmasters-cn-tools-certificate-maker/archive/refs/heads/main.zip)，然后解压。
2. 在解压后的文件夹中，用浏览器打开 `index.html`。
3. 页面右上角显示“模板已就绪”后，填写信息并点击“生成奖状”。详细操作见[怎么使用](#怎么使用)。

请将 `index.html`、`styles.css`、`app.js`、`zip.js`、`roster.js` 和 `template-data.js` 保留在同一文件夹中。

也可以直接在线使用（若仓库所有者已开启 GitHub Pages）：

<https://regan-sun.github.io/toastmasters-cn-tools-certificate-maker/>

## 它能做什么

你只需要填好会议和获奖信息，它就会按照现有的 District 118 奖状样式，自动生成一张或多张奖状图片。

它可以帮你：

- 填写会议经理、会长和证书日期
- 修改奖状顶部标题、颁发文案、说明文字和落款标签
- 使用预设奖项，也可以自己添加、删除或修改奖项
- 给每个奖项填写获奖人姓名
- **整段粘贴名单，自动拆成奖项和获奖人**（支持全角/半角冒号、制表符、逗号、竖线、序号、emoji 等写法）
- 从剪贴板或`.txt` / `.csv` 文件直接导入名单
- 导入后先预览逐条确认，确认无误再替换当前列表
- 一次生成所有获奖人的奖状
- 先在页面里预览，再单张保存、打包成 ZIP，或直接存进选定文件夹
- 自动按“奖项-获奖人-奖状.png”命名图片
- 记住你上次填写的内容，并保留最近 20 场会议的历史，奖项设置可一键沿用
- 名单或模板改动后自动作废旧预览，避免误用上一次的奖状

## 用大白话说，什么时候用它

比如今晚俱乐部开完会，评出了三位获奖者：

- 最佳主持人：小王
- 最佳即兴：小李
- 最佳点评人：小张

你把这三项填进去，点击“生成奖状”，工具就会一次生成三张对应的奖状。你可以检查预览，确认没问题后保存到电脑或手机，再发给获奖者。

## 怎么使用

### 第一步：填写基本信息

输入会议经理、会长和证书日期。

### 第二步：检查奖状文字

如果使用默认模板，可以直接跳过。需要调整时，可以修改：

- 顶部标题
- 颁发文案
- 说明文字
- 左侧落款标签
- 日期栏下方文字
- 右侧落款标签

### 第三步：填写奖项和获奖人

每一行对应一张奖状。填写奖项名称和获奖人姓名即可。

不够用时点击“添加奖项”；想重新开始时，可以清空获奖人。

**批量粘贴（推荐）**：展开「批量导入名单」，把整段名单粘进去点“解析名单”。以下写法都能识别：

```
最佳主持人：小王
最佳即兴:李四
最佳点评人	张三
1. 最佳小蜜蜂 王五
✅ 最佳主持 王小明
```

解析后会先显示逐条预览，每条都可以当场改。确认无误再点“应用并替换当前列表”。

像「本周共33人参加」这类叙述句会被自动跳过，不会混进奖状里。

### 第四步：生成并保存

点击“生成奖状”，等待预览出现。确认内容和姓名无误后：

- **存到文件夹**（推荐，Chrome/Edge）：选一个目录，所有奖状直接落盘，不经过下载栏
- **打包下载 ZIP**：一次拿到一个压缩包，解压后是全部单张 PNG
- **单张保存**：只想存某一张时，用卡片上的“保存”按钮
- 在微信中浏览时，可以长按每张奖状图片保存

### 用上一场的奖项设置

生成过一次后，该次会议会自动进入「历史会议」。下次开会时点“载入”，奖项设置和日期一并带入，只要改人名就行。

## 它不会做什么

这个工具负责排版和生成图片，不负责替你决定谁获奖，也不会自动判断奖项是否正确。

- 不会自动读取会议记录并评选获奖者
- 不会自动修改你输入的姓名
- 不会把奖状发送到微信群或个人聊天
- 不会替你完成打印、邮寄或发布
- 生成前仍建议认真检查姓名、奖项和日期

## 使用时的几个小提醒

- 姓名和奖项不能为空，否则无法生成对应奖状。
- 生成前请检查中文姓名是否有错别字。
- 如果在微信里无法批量下载，这是微信浏览器的限制，不是奖状生成失败。
- 模板资源需要和网页文件一起加载；如果页面显示“模板缺失”，请确认没有单独拷走 `index.html`。
- 填写内容保存在当前浏览器的本地记录中，换浏览器或清理浏览器数据后不会自动带过去。

## 部署

推送到 `main` 分支即自动部署到 GitHub Pages，无需构建步骤（本站是纯静态文件）。

首次启用需要在仓库设置里切一次：

1. **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**
2.之后每次 `git push` 到 `main` 会自动发布

配置文件是 `.github/workflows/deploy.yml`。它用最小权限（只读代码 + 写 Pages），并设置了并发取消：连续推送时只保留最新一次部署。

根目录的 `.nojekyll` 是必要的——它让 GitHub 跳过 Jekyll 处理，直接原样发布文件，避免中文名和 `.js` 被加工。

注意 Pages 默认**公开可访问**，`template-data.js` 内含品牌素材，公开托管前请确认符合对应商标授权要求。
